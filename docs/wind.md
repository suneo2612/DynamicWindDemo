# 風のデバッグとシミュレーション

[README に戻る](../README.md)

## 風力階級

`demo/wind/beaufort.h` の `ClassifyBeaufort()` は、風速（m/s）を
ビューフォート風力 0～12 と日本語名称に分類します。各階級はその下限値以上で
切り替わり、32.7 m/s 以上は風力 12 の「颶風」です。

負の値や非有限値は拒否します。

## 風発生器

`demo/wind/motor/wind_motor.h` の `WindMotors` は、モデルを持たない風発生器の
設定と生成要求を管理します。球・円錐・円柱を指定でき、生成要求は
`ProcessRequests()` で受付順に処理します。上限を超えた要求は失敗し、空き待ちは
しません。

`TakeResult()` で成否・補正後の設定・補正理由を取得できます。
設定は `Set()` で変更し、風の更新側は `Snapshot()` で有効な発生器のコピーを
取得します。

瞬間風を反映した後は `CompleteInstant()` で枠を解放してください。
Entity の移動による位置や方向の変更は利用側で行います。

CMake の `DYNAMIC_WIND_ENABLE_DEBUG_MOTORS` を `ON` にするとデバッグ専用枠と
デモの風デバッグ画面が有効になります。標準の VS プリセットでは `ON`、
CMake オプション単体の既定値は `OFF` です。構成方法は [README](../README.md#風のデバッグ)
を参照してください。

既定の通常枠は 32 個、有効時のデバッグ専用枠は 16 個で、
両者は別々に管理します。

## デバッグ画面の操作

### 発生器と基本風

有効時はデモに「風のデバッグ」画面が現れます。

「新しい発生器」でカメラの前方に
初期位置を用意し、形状・継続／瞬間・位置・方向・風速・寸法などを入力して
「発生器を生成」を押します。

生成後は一覧から選択して設定を適用・削除できます。
発生方法は生成後に変更できません。設定が補正された場合や枠が不足した場合は
画面に理由を表示します。風速からビューフォート風力階級と名称も表示します。

基本風の入力は「基本風を適用」で反映されます。

「フィールドのクリックで生成」を有効にすると、フィールド表面を左クリックした位置に
編集画面の形状・風速・方向などを使って新しい発生器を生成します。位置のみクリック地点に
置き換えます。既定では無効です。

UI 上やフィールド外のクリックでは生成せず、手前に
移動物体がある場合もその背後には生成しません。発生器の専用枠が満杯の場合は画面に
理由を表示します。

発生器の範囲は球・円錐・円柱の線で表示し、無効な発生器は灰色にします。
線はモデルの手前だけに表示され、「発生器の形状を表示」で表示を切り替えられます。
瞬間発生器は固定周期の更新で一度反映された後、一覧と表示から消えます。

### 管理空間と断面表示

風の管理空間は物体の位置と進行方向を基準に追従し、「風管理空間の範囲を表示」で
ワイヤーフレームを切り替えられます。

「風のデバッグ」の「セルの格子を表示」で、
管理空間内の全セルの境界を 1 m 間隔の立体格子として表示できます（初期状態は非表示）。
格子は管理空間の移動に追従し、モデルに遮られます。

「風管理空間」画面では選択した Y 断面の
セルごとの風速ベクトルを一覧表示し、風速 XYZ 成分を RGB に割り当てた 3D
テクスチャの断面プレビューを 5 枚表示します。各プレビューの Y インデックスは
個別に指定できます。

RGB の各成分は、風速成分 -32.7 / 0 / 32.7 m/s を
それぞれ 0 / 128 / 255 に対応させ、範囲外は端の色に制限します。

「セルの風向きを表示」を有効にすると、各セル中心に風向きの 3D 矢印を表示します
（初期状態は非表示）。GPU 上の最新の風からインスタンシングで描画し、無風のセルには
表示されず、モデルに遮られます。長さは風速に比例し、32.7 m/s 以上で最大 0.7 m です。

矢印の RGB は断面プレビューと同じ風速 XYZ 成分の対応を使います。
GPU の風を直接使うため、
非同期読み戻しを使う一覧や断面プレビューと表示フレームが異なる場合があります。
全セルを描画するため GPU 負荷が増える場合があります。

各断面画像は下のスライダーまたは画像上のマウスホイールで 1～16 倍に拡大でき、
画像を左ドラッグすると表示範囲を移動できます。ホイールではカーソル位置を中心に
拡大・縮小し、画像ごとに表示範囲を保持します。

風によるモデルの変形・移動はまだ実装していません。

## 風の占有率と GPU 更新

`demo/wind/simulation/occupancy.h` の `CalculateOccupancy()` は、球・円錐・円柱と
1 m セルの重なりを近似します。完全に内包されるセルは 100% となります。

境界では
セルを分割し、マーチングキューブ法で各小立方体の辺の交点を結んだ境界面と
立方体の外面から閉じた領域を作り、体積を求めます。対角の頂点が内側にある面は
面の中心の内外により交点の接続を決めます。

小立方体の頂点が全て外側でも、
辺・面・立方体の中央に重なりが見つかれば一段階細分化します。細い重なりを
見逃す場合があります。境界の輪郭が複数ある場合はそれぞれ独立に三角形で閉じる
方式であり、内部の複雑な分岐を再現するものではありません。

分割数は `OccupancySettings` で 1～4 に設定でき、既定値は 4 です。
5 以上の値はエラーになります。

この CPU API は以下の GPU 風更新とは異なる
近似方法を使用します。
占有率そのものの可視化はまだ実装していません。

`demo/wind/simulation/wind_grid.h` の `WindGrid` は、OpenGL 4.3 のコンピュート
シェーダーと符号付き 16.16 固定小数点の 3D テクスチャを使い、隣接セルへの風の
分配、境界からの基本風の流入、基本風への減衰を行う途中段階の実装です。
更新は `Step()` を呼び出して行い、テクスチャは `Textures()` から取得します。

発生器管理器、管理空間の整数原点、占有率設定を渡す `Step()` では、
発生器の設定を GPU に送り、セルごとに並列で占有率と方向・距離減衰を求めます。

境界セルの占有率はセルを各辺 1～4 分割した小立方体の中心点で判定し、
内側の点数の割合で近似します。細い重なりは標本点に当たらず見逃す場合があり、
従来のマーチングキューブ法とは結果が異なります。

GPU の更新で
継続風を基本風と合成し、瞬間風を一度加えます。瞬間発生器がある場合は GPU の
処理完了を待ってから枠を解放します。失敗時は発生器を保持します。発生器の
設定変更は次回の呼び出しに反映されます。呼び出し中の発生器管理器の同時変更は
できません。

発生器の一覧・設定、管理空間の原点・寸法と占有率の分割数が変わらない間は、
GPU 上のセルごとの寄与を再利用します。瞬間風は更新成功後に
発生器が解放されるため、次の更新で再計算されます。再計算時は確実に内側または外側と
判定できるセルの標本検査を省きます。GPU 処理が失敗した場合、CPU への自動切り替えはせず、
エラーを通知します。

既存 API の座標範囲との互換性のため、管理空間は整数メートルを表現できる
-16,777,216～16,777,216 の範囲に収まる必要があります。GPU の判定には
管理空間の原点からの相対座標を使用します。

### 処理負荷と分配方式

「風の処理負荷」ウィンドウには直近の CPU 更新時間と、GPU タイマークエリで非同期に取得した
風更新・発生器計算の時間を表示します。GPU の値は完了済みの直近計測なので、
表示中のフレームの値と一致しない場合があります。発生器寄与がキャッシュされた更新では
発生器計算時間は新たに計測されず、表示は最後に完了した再計算の値です。

分配方式の既定値は風速比例の方式 B です。60 Hz で 64 m/s なら 25%、32 m/s なら
12.5%、無風なら 0% を送り出します。

周期を変更すると、60 Hz での割合 `r` と更新時間
`t` 秒から `1 - (1 - r)^(60t)` を求めます。境界からの流入にも基本風の風速に
応じた同じ割合を使います。`SetDistribution()` は 64 m/s における割合を変更し、
`SetDistributionMethod()` で風速によらない方式 A に切り替えられます。

デモでの風の利用は、デバッグ画面とその確認用シミュレーションに限ります。
作成から破棄まで有効な OpenGL 4.3 コンテキストが必要です。

方式選定は NVIDIA GeForce RTX 5080、OpenGL 4.3 / NVIDIA 610.88、Release で
比較しました。64×32×64 セルに 0～64 m/s の複数の風速・風向きを配置し、
発生器と描画を除いた GPU 更新を同じ初期状態から各 8 回行います。2 組の予熱後に
15 組を交互の順序で計測し、組ごとの B/A 時間差の中央値を使います。2 回の独立した
計測で中央値はそれぞれ -0.32%、+0.01% だったため、5% 基準に従い B を採用しました。
一部の計測には外れ値があり、結果は GPU・負荷・風の分布に依存します。
性能が問題になる場合は方式 A を明示的に指定できます。

## 管理空間と読み戻し

`demo/wind/wind_region.h` の `WindRegion` は、1 m のセル単位でワールド軸固定の
管理空間を追従させます。空間の寸法、基準位置、移動・回転の閾値および座標系は
`WindRegionSettings` で指定します。追従距離が基準位置から空間の端までの距離を
超える設定は拒否します。

`demo/wind/simulation/wind_simulation.h` の `WindSimulation` は、管理空間の追従と GPU の
風速格子を連動します。移動時に重なったセルを保持し、新領域をその時点の基本風で
初期化します。`Advance()` に毎フレームの経過秒数、単調増加する 1 以上のフレーム番号、
位置・視線、基本風と発生器管理器を渡します。初期値は 60 Hz で、経過時間を蓄積して
必要回数更新します。`SetUpdateRate()` で実行中に周期を変更しても未処理時間は保持します。

`SetDistribution()` は 60 Hz における分配割合、`SetHalfLife()` は目標風との差の半減時間を
設定します。初期値はそれぞれ 25%、2 秒です。既定の方式 B では 25% は 64 m/s の値です。

既存のコード向けに `wind_grid.h` からも `WindSimulation` を参照できます。
内部実装では、発生器の GPU 寄与とキャッシュを `wind_motor_gpu`、
非同期読み戻しを `wind_readback` に分けています。CPU 側の発生器寄与を計算する
`motor_field` とは近似方法が異なり、GPU 更新の代替には使用しません。

`Advance()` は GPU からの非同期読み戻しも処理します。`Sample()` は取得済み風、初回の
準備中、または現在・取得済み範囲の外における代替風の状態を返します。

取得済み風には
転送元のフレーム番号を含み、準備中・代替風のフレーム番号は 0 です。初回の準備中は
基本風を返し、範囲外の代替風は基本風または無風を選べます。

転送が完了していない場合は
以前の取得済みデータを使い、読み戻し時の空間位置も合わせて保持します。3 つの転送枠が
全て使用中なら新しい転送を見送り、後のフレームで再試行します。

入力と追従位置の検証後に
失敗した `Advance()` は経過時間を保持するため、その再試行では追加の経過時間を二重計上
しないよう 0 秒を渡してください。入力や追従位置の検証時に失敗した場合、経過時間は受理しません。
